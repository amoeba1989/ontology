# 01 · 项目速览

## 它是什么

一个 Python 库 + 一个探索型 Web UI，把"文档/数据 → 实体关系 → 知识图谱 → 规则推理 → 决策留痕"这条链做成了一个可 `pip install` 的工具集。官方口径是 *Graph-Native Infrastructure for Context and Accountable AI Systems*，主打**可解释、可追溯、可问责**，目标客户是高合规行业。

拆开这句口号，实际交付的是四件事：

1. **知识工程管线** — 42 个接入器取数（DB/仓库/SaaS/流/文件/网页）→ 23 种文档解析 → 6 种切块策略 → 8 家 LLM 抽取 → 消歧归一 → 冲突裁决 → 入图
2. **本体管理** — 从数据自动归纳草案本体，生成 TTL/OWL，用 SHACL 做形状约束校验，带版本与 diff
3. **确定性推理** — 规则引擎（含 RETE 网络）、Datalog、SPARQL、溯因推理，每次派生都产出证据链
4. **决策与上下文** — Context Graph + `Decision`/`Precedent`/`Policy`/`PolicyException` 数据模型，把"当初为什么这么判"变成可查询对象

## 形态与入口

| 形态 | 证据 | 说明 |
|---|---|---|
| 库 | `semantica/__init__.py` | `__all__ = []` + PEP 562 懒加载，公共 API 刻意薄，只暴露 15 个 submodule proxy |
| CLI | `semantica/cli.py` | 无子命令时打印品牌 banner + Graph/Vector Store/Profile 状态表；有 `semantica shell` REPL 与 `completion` |
| REST 服务 | `semantica/server.py` | FastAPI，`SEMANTICA_API_KEY` 未设置时直接 503（默认拒绝） |
| MCP 服务 | `semantica_mcp/mcp/server.py` | 手写 JSON-RPC 2.0 over stdio，18 个工具 |
| Worker | `semantica/worker.py` | 异步任务侧 |
| Web UI | `explorer/`（React 19 + Vite + sigma/graphology + Monaco） | 12 个 workspace，构建产物直接输出进 `semantica/static` |
| 插件 | `plugins/skills/`（17 个 `SKILL.md`）、`plugins/hooks/hooks.json` | 面向 Claude Code 一类 agent 的技能卡与 shell 钩子，不是平台内建扩展点 |
| 集成 | `integrations/{agno,crewai,google_adk,langchain,open_ontologies,openclaw}` | 2–6 个文件的薄适配层，包 `AgentContext`，不接内核 |

## 存储：宣称"多语言图存储"，实际有主次

- `semantica/graph_store/` — Neo4j、Apache AGE、FalkorDB、Neptune
- `semantica/triplet_store/` — Jena、Blazegraph、Oxigraph、RDF4j、Anzo
- `semantica/vector_store/` — 8 种（FAISS、Qdrant、Milvus、pgvector 等）

选择方式是 `config.py` 读 `*_DEFAULT_BACKEND` 环境变量 + 构造函数里 `if backend ==` 分支，没有注册表抽象。**RDF 与 LPG 并非对等双支持**：核心 `kg/knowledge_graph.py` 与 `context/context_graph.py` 都是内存 LPG（networkx 风格），`triplet_store` 主要作为导出与 SPARQL 查询旁路。

## 部署形态

`Dockerfile` 多阶段构建、基础镜像按 digest 锁、`apt --only-upgrade` 打 Debian 安全补丁并逐条注释 CVE、`USER semantica`、`HEALTHCHECK` 打 `/api/health`、运行时装完依赖后**把 pip 卸掉**以消除 vendored urllib3 的 CVE。`docker-compose.yml` 只有两个服务（explorer + falkordb）。另有 `deploy/` 覆盖 7 种平台（K8s、Helm、Bicep、CloudBuild 等），K8s manifest 里有 requests/limits 与默认拒绝的 NetworkPolicy。

## 需要警惕的口径

README 与包内文档里的这些词，**在代码里是打折的**：HermiT/Pellet 级 OWL DL 一致性推理（占位实现）、因果推理（实为决策图遍历）、多级审批编排（`ApprovalChain` 只是单条审批流水记录）、端到端溯源默认生效（溯源管理器实际未接入默认管线）。详见 [03-设计亮点与薄弱点.md](03-设计亮点与薄弱点.md)。
