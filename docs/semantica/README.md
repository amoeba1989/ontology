## 一句话结论

Semantica 真正的护城河不是代码量，也不是 MIT + 拥挤的 context-graph 赛道，而是**工程纪律**：溯源与真值维护被建成一等公民、CI 里有"已知失败债务台账"这种逼自己还债的机制、每条被忽略的 CVE 都要写可达性论证。这些恰恰是小团队最容易补、也最容易长期省命的部分。而它在"标准语义"上的宣传（OWL DL 一致性、HermiT/Pellet、因果推理）与实现差距明显——**我们不需要因为看到这些词就推翻现有架构**。

## 与知彼的关系定位

两者不是同类产品：Semantica 是一个 Python 库 + 探索型 UI，强在知识工程与推理的**方法论**；知彼是一个交付给业务方使用的**平台**，强在多源接入、发布流水线、场景与权限。因此这组笔记的取舍标准是：**方法论和数据结构照抄，平台形态和产品外壳不抄。**
