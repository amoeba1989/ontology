# 客户演示与技能问答

进入「业务交付工作区」查看四组独立合成数据：慢病健康、学术文献、建筑运维、电商供应链。每组包含真实 SQLite 数据源、数据管道、对象映射、关系、SQL 业务约束、已发布本体、应用、三项技能及智能体。

演示顺序：数据接入 → 资产目录 → 管道运行 → 本体对象与关系 → 运行应用 → 技能管理 → 智能体问答 → 执行记录。供应链可提问「当前哪些订单存在库存或物流风险？」。问答先调用已授权技能读取数据库，再由模型总结；页面展示工具证据与执行编号。人工复核需进入运行应用填写参数并执行，AI 不自动写回业务数据。

## 模型配置

演示助手优先使用已经保存的 DeepSeek 模型（系统配置 `ai.models` 或模型管理），不复制、不覆盖密钥。明确指定 `model_id` 的智能体使用绑定的模型。DeepSeek 模型名通常为 `deepseek-chat`，接口需兼容 OpenAI 原生工具调用。配置已保存不等于连接成功：「验证模型问答」实际调用模型、技能和数据库，并保存 `AgentTrace` 与 `SkillRun`。

## 安装与验收

部署会先备份平台 SQLite 数据库，再执行 `python scripts/customer_demo.py --install --check-ai`。安装清单 `customer_demo_packs` 保证已完成样例不会被重复初始化；数据放在挂载卷的 `delivery-examples/` 中。现有业务库、项目和模型密钥不会被覆盖。修改演示源数据后，在交付工作区重新运行该项目的管道，查询和问答会读取更新后的输出数据。

四组数据的初始规则结果分别为 3、4、5、4 条。技能查询每对象最多 20 行，质量技能是契约及取样检查，不等于完整数据审计。规则管理使用可执行 SQL 约束；BIM 碰撞为包围盒示例，医学数据完全合成、仅用于流程演示，不用于诊断和处方。当前版本不宣称实现通用 OWL/SWRL 推理或完整数字孪生。

GitHub Actions 收集与提交 SHA 对应的 `customer-demo-verification` 报告，包含菜单记录数、四组数据库技能检查及真实模型问答结果，不包含密钥或问答业务明细。任何技能失败、模型拒绝工具调用或接口不通都会使验收失败，不能仅凭容器启动认定演示就绪。
