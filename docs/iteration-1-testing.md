# 迭代 1 测试说明

本版交付“AI / 表单共用建模草稿 + 基础规则审核 + 技术依赖梳理”。代码尚未推送 main 或更新生产，供先测试。菜单入口：本体中心 → 本体构建 → AI / 表单建模；直接路径 `/builder/drafts`。

## 独立测试部署

下载本次完整源码包，上传 ECS 并解压到独立目录，例如 `/opt/ontology-uat`。不要覆盖正在运行的 `/opt/ontology`。测试环境使用独立数据库卷和 8090 端口，不读取生产模型密钥或生产数据。

在源码根目录执行：

```bash
umask 077
read -rsp '设置测试管理员密码: ' UAT_ADMIN_PASSWORD
printf '\n'
printf 'UAT_ADMIN_PASSWORD=%s\nUAT_SECRET_KEY=%s\nUAT_WEB_PORT=8090\n' "$UAT_ADMIN_PASSWORD" "$(openssl rand -hex 32)" > .env.uat
unset UAT_ADMIN_PASSWORD
docker compose --env-file .env.uat -p ontology-uat -f compose.uat.yml up -d --build
docker compose --env-file .env.uat -p ontology-uat -f compose.uat.yml ps
```

密码建议使用 16 位以上英文字母和数字，避免 dotenv 特殊字符。访问 `http://服务器公网IP:8090/builder/drafts`，登录名 `admin`，密码为刚设置的值。如果访问不到，检查 ECS 安全组是否允许你的访问来源连接 8090。构建需要拉取容器镜像与依赖；本次尝试 Docker 构建时，构建容器无法解析依赖镜像站域名，故容器构建/启动尚未通过验收。Python 虚拟环境与 Vite 构建及浏览器操作已通过验证。

第一次可先测试手工建模；测试 AI 时，在**测试系统**的模型管理/系统配置中填入兼容 DeepSeek 的模型名、API 地址和密钥。不要把密钥粘贴到聊天中。生产环境配置不自动复制到此测试库。

停止测试环境（保留数据）：

```bash
docker compose --env-file .env.uat -p ontology-uat -f compose.uat.yml down
```

不要添加 `-v`，否则会删除测试数据库卷。该命令不停止生产 Compose 项目。

## 建议按这 6 项验收

| 步骤 | 操作 | 应看到什么 |
|---|---|---|
| 1. 模板起步 | 新建草稿 → 载入无人机演示模板 → 保存 | 3 个对象、观测空域关系、离地高度规则；明确标记模板来源 |
| 2. 人工编辑 | 修改名称、属性单位、关系；保存并刷新 | 内容仍在；从左侧可重新打开草稿 |
| 3. 样例验证 | 规则与样例 → 保存并测试全部样例 | 高度 30 合格、-5 违反约束，均符合预期；字符串高度不能冒充数值 |
| 4. 审核控制 | 填写依据、前提、例外 → 核对并接受；再修改阈值保存 | 首次接受成功；改动后回到待审核，不能跳过确认 |
| 5. 模型入库 | 接受或拒绝全部规则 → 写入本体管理 | 对象进入对象管理，接受的规则以草稿进入规则管理；重复点击不重复创建 |
| 6. AI 辅助 | 新建另一草稿，描述电商库存场景 → AI 生成建议 → 预览 → 采纳 | 先生成建议而不覆盖原草稿；采纳后可人工改；配置/网络失败有明确错误 |

已有同名对象时，选择“已有对象复用”，不要反复创建。复用对象定义在此只读；原对象仍在现有对象管理中编辑。

## 当前边界与下一版

当前规则只在你提供的正反样例上验证；这不能证明全量业务数据合格，也不能证明 AI 推荐规则符合所有行业法规。前提与例外目前是审核说明，下一版将补结构化适用范围与真实数据执行。
