## 0. 启动与登录

### 启动系统
```bash
# 方式一：一键脚本（Windows）
start.bat            # 自动装依赖 + 起后端(8001) + 起前端(5177)

# 方式二：手动分别启动
# 后端
cd backend
cp .env.example .env        # 配置 DATABASE_URL / LLM_API_BASE / LLM_API_KEY / LLM_MODEL
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8001

# 前端
cd frontend
pnpm install && pnpm dev
```

| 入口 | 地址 |
|------|------|
| 前端界面 | http://localhost:5177 |
| 后端 API 文档 (Swagger) | http://localhost:8001/docs |

### 登录
- 首次启动自动建表、执行迁移，并创建默认管理员：**`admin`**，密码取环境变量 `BOOTSTRAP_ADMIN_PASSWORD`；未设置该变量时回落到代码内置默认值（见 `backend/app/api/v1/auth.py`）。账号已存在时不会被重置，登录后请立即改密。
- 登录成功后 token 存于 `localStorage`，未登录访问任意页面会跳转 `/login`。

## 2. 本体的核心概念（操作前必须理解）

- **对象（Entity/Object）**：业务实体，如"客户""订单"。带 `tier` 分层：
  - **Tier 1 核心** / **Tier 2 领域** / **Tier 3 场景**
- **属性（Attribute）**：对象的字段。关键是它绑定物理落点 `source_table` + `source_field`，并有映射状态 `data_status`（默认"未确认来源"）。
- **关系（Relation）**：对象之间的连线，含 `rel_type`（关系类型）、`cardinality`（1:1 / 1:N / N:N）、`acyclic`（是否无环）。
- **逻辑层**：规则/函数/行动都**挂在对象上**，让本体"可执行"。
- **双轨版本**：你日常编辑的是「实时本体」；发布时会冻结成「版本快照」，供 Agent/流程稳定引用。

## 3. 本体操作主流程（推荐顺序）

### 步骤 A：准备数据（数据集成）
1. 进入 **数据接入** `/data/connections` → 新建连接，选连接器类型，填地址/账号 → 测试连通性。
2. 进入 **资产目录** `/data/assets` → 触发 Schema 同步，查看表结构、样本预览、数据画像。
   > 没有真实数据源也可跳过，先用"手动构建/文档构建"建纯语义本体。

### 步骤 B：构建本体（四选一，产出"实时本体"）

**B1. 手动构建** `/builder`
- 顶部"工具选择"下拉：本地构建 / Protégé / WebOWL / VocBench。
- 选"本地构建"会自动创建构建会话（BuilderShell），手动增删对象、属性、关系。

**B2. 模板构建** `/builder/template`（3 步向导）
```
① 文件导入 → ② 专家审核 → ③ 水合验证
```

**B3. 文档构建** `/builder/doc`（6 步向导，LLM 抽取）
```
① 需求与文档(上传 Word/PDF/Excel)
② AI对话抽取(SSE 流式)
③ 资产映射
④ 映射确认
⑤ 专家审核
⑥ 水合验证
```

**B4. 资产构建** `/builder/ai`（6 步向导，基于已接入数据）
```
① 业务描述(输入领域/业务上下文)
② 选择数据表(可下钻多个 domain)
③ 选择文档
④ AI提取(LLM 产出对象/关系/规则/动作草稿，自动回写 backing_asset)
⑤ 专家审核(Step2Review：逐条确认实体、属性、关系)
⑥ 水合验证(Step3Hydrate：4 阶段真实数据验证)
```

> **专家审核**：AI 产出的都是"草稿"，必须在此逐条确认/修改后才落库。
> **水合验证（Hydration）**：4 阶段 SSE 流式进度——① 数据接入验证 ② 本体实例化（启发式评分+LLM兜底）③ 关系映射验证（JOIN 键检查）④ 策略输出（主键唯一性、必填空值率）。

### 步骤 C：管理对象与关系 `/browser`
- 顶部按 **Tier 分层卡片** 汇总，点击卡片按层级筛选；也可"全部"。
- 搜索框实时检索对象；「新建对象」跳转 `/builder`。
- 点选对象 → 右侧详情，Tab 切换查看 **属性 / 关系 / 规则 / 动作 / 函数**；「编辑」修改对象。

### 步骤 D：映射管理 `/data/mapping`
1. 左侧选实体（可搜索）。
2. 「扫描资产」→ 系统列出候选物理表/字段。
3. 「重新推荐」→ 启发式 + LLM 给出映射建议（带置信度、理由 `reason`）。
4. 「采用全部高置信」批量接受，或逐行手填列名 / 从候选中选择。
5. 「应用映射」→ 写回属性的 `source_table`/`source_field`，`data_status` 更新。
   > 也支持「一键组合映射」(oneClickCombo) 处理主表+关联表。

### 步骤 E：图谱探索 `/studio`
- 双层画布：**本体 Schema 层**（对象类型关系图）+ **实例数据层**。
- 左侧搜索/选择对象类型；右上切换视图、刷新实例数、全屏。
- 点节点 → 右侧详情面板，Tab 查看 属性/关系/规则/动作/函数（懒加载），可"在实体详情中打开"或调用讲解员(narrator)。

### 步骤 F：定义逻辑层
- **规则管理** `/logic/rules`：给对象加声明式规则。支持两种模式——表达式(`condition_expr`) 与 结构化条件(`conditions_json`)。设优先级、绑定行动 `action_id`。
- **函数管理** `/logic/functions`：定义派生属性计算函数，含 Schema 与测试沙箱。
- **行动管理** `/logic/actions`：定义参数化行动，选执行器类型（API调用/SQL执行/修改属性/调用函数/通知/自定义脚本），设前置条件、手动或自动触发。

### 步骤 G：发布本体（版本流水线）`/ontology/publish`

这是本体从"编辑态"进入"生产态"的关键，完整状态机：
```
draft(草稿) → pending_approval(待审批) → published(已发布, is_active)
                                    ↘ rejected(驳回)
published → (rollback) 生成新 draft/pending 版本
```
操作顺序：
1. **「创建新版本」** → 填名称/说明，生成 draft。
2. draft 状态下 **「添加实体」** → 勾选要纳入本次发布的对象（深拷贝为快照，自动同步关系）。可「移除」。
3. **「一致性检查」** → 校验：每个实体是否绑定数据源、映射率是否 ≥50%；关系两端实体是否都在版本内（悬空关系报错）。**不过不能提交**。
4. **「预览影响面」** → 对比旧 active 版本，列出破坏性变更（deleted/renamed）及受影响的 AIP 场景 / Agent。
5. **「提交审批」** → draft → pending_approval。
6. 审批人 **「审批通过」** → 发布：旧版本失活、本版本置 active、实体状态升级、**自动把受影响的下游场景/Agent 标记 `ontology_stale`（过时）**。或 **「驳回」** 填原因。
7. **「回滚到此版本」** → 基于历史已发布版本重新生成一个待审批版本（保留审计链）。

### 步骤 H：对外服务与消费
- **本体服务** `/service/api`：查看/调用对外本体 API、OSDK。
- **智能体管理** `/agent/manage`：新建 Agent，绑定本体版本(`ontology_version_id`)与实体(`entity_ids`)，配置技能。Agent 用 ReAct 循环，通过本体语义查询数据、评估规则、执行行动。
- **流程编排 (AIP)** `/aip`：可视化拖拽节点编排多步流程，节点类型含本体查询、关系遍历、规则评估、LLM 推理、意图识别、条件分支、数据源、技能等；支持 Webhook 触发。

## 4. 端到端演练（一条最短路径）

以"从零建一个可用本体"为例：
1. `/data/connections` 建一个 MySQL 连接 → `/data/assets` 同步出 `customer`、`order` 表。
2. `/builder/ai` 资产构建：填业务描述 → 选 `customer`/`order` 表 → AI 提取 → 专家审核确认 → 水合验证通过。
3. `/browser` 查看生成的"客户""订单"对象及关系，按需编辑。
4. `/data/mapping` 确认属性映射（采用高置信建议 → 应用）。
5. `/logic/rules` 给"客户"加一条规则（如"欠费>100 且 逾期>30天 → 高风险"），`/logic/actions` 建一个"发送催缴通知"行动并绑定。
6. `/ontology/publish` 创建版本 → 添加实体 → 一致性检查 → 提交审批 → 审批通过。
7. `/agent/manage` 新建 Agent 绑定该本体版本 → 用自然语言问"筛选高风险客户"，Agent 自动调 `screen_users_by_rule` 等工具。
8. `/studio` 图谱探索查看整体语义网络；`/ops/monitor` 看运行指标；`/agent` 追踪执行链路与 Token 消耗。

## 5. 常见问题

- **提交审批失败** → 多半是一致性检查没过：实体未绑定数据源，或属性映射率 <50%，或存在悬空关系。回到映射管理补齐。
- **Agent/场景显示"本体过时(stale)"** → 你发布了含破坏性变更（对象删除/改名）的新版本。检查受影响的绑定并更新。
- **AI 抽取结果不理想** → 在"专家审核"步逐条修正；或在业务描述里补充更明确的领域上下文。
- **默认 LLM 未配置** → 编辑 `backend/.env` 的 `LLM_API_BASE`/`LLM_API_KEY`/`LLM_MODEL`，或在 `/settings/models` 配置多模型。
```
