# 六步业务交付闭环 V1

入口：工作台 → 业务交付工作区（`/workspace/projects`）。

需求分析 → 数据源表 → 数据处理 → 子图建模 → 本体库 → 本体应用。

## 第一版的操作流程

1. 新建项目，填写目标、使用者、核心问题、预期操作和验收条件。
2. 选择资产目录中的结构化数据。需要先完成连接和字段采集。
3. 选择真实数据管道及其输出资产，运行项目管道。数据已经规范时可选直连，并说明原因。
4. 选择对象与行动。对象需要有效主键、字段映射，以及指向项目输出资产的主绑定。
5. 选择已发布本体版本，或者由管理员点击“校验并发布项目本体”。项目发布不切换全局活动版本。
6. 真实试运行，核对样本；填写业务验收结果后保存并重新试运行，发布应用。
7. 打开运行页，查看数据、刷新来源、执行业务行动。结果记录在项目的运行记录中。

草稿修改不改变已发布应用的字段映射。运行应用读取当前业务数据；资产结构改变时拒绝继续查询，要求重新校验发布。
项目当前仅对创建者和管理员开放，未提供匿名公开链接或团队共享。

## 四组独立验收场景

管理员点击“非军事验收样例”，可创建医学、文献、BIM、供应链项目。每次创建使用新的独立 SQLite 数据库，位于 `data/delivery-examples`，不会连接真实医疗或业务数据库。

| 场景 | 初始规则结果 | 覆盖内容 |
| --- | --- | --- |
| 慢病健康管理 | 3 条 | 配置的药物冲突、异常指标证据、药物过敏提示 |
| 学术文献 | 4 条 | 上位主题检索下位文献、单向引用、同作者同主题聚合 |
| BIM 运维 | 5 条 | 维保到期、材料寿命、轴对齐包围盒重叠、连通空间影响 |
| 电商供应链 | 4 条 | 安全库存缺口、订单库存不足、物流不可达、补货产能不足 |

场景均包含核心对象、关系谓词、属性映射、可执行约束和人工复核行动。约束通过真实 SQL 执行；没有实现通用 OWL/SWRL 推理器、IFC 导入、精确几何碰撞、语义聚类或临床决策系统。医学数据与药物完全为合成测试内容，异常不作为确诊结论。文献子主题不会自动继承全部上位主题文献。BIM 一跳空间影响是样例假设。

测试会实际创建源表、运行加工、发布本体和应用、查询结果、执行参数化 SQL 人工复核、重复运行、清空源事实后检查旧推理结果是否消失。发布样例本体不会替换平台全局活动版本。

## 修复与复用

- 复用现有连接、资产、对象绑定、版本校验、真实管道、数据执行与审计服务。
- 模拟管道不计入交付就绪；真实管道编辑后需要重新运行。
- 输出资产必须对应处理目标，源查询须使用项目选中的源表。
- 空的全量刷新会清理旧结果，避免保留过时的风险项。
- 本体版本同步关系时读取最新对象集合，修复添加对象后因缓存导致关系遗漏的问题。
- SQL 行动原来只返回模拟成功，现已执行真实参数化 SQL。使用 `:name` 占位符；旧 `$name` 模板会提示迁移，不再拼接输入值。
- V1 应用可挂载真实 API 调用和 SQL 行动，其他未完整执行的行动类型暂不计入就绪。
- 日常 Docker 部署不再调用演示种子脚本。首次演示初始化可显式使用 `SEED_DEMO_DATA=1`；军事样例初始化改为保留已有记录。
- GitHub Actions 新增后端闭环测试和前端构建，验证成功后部署。

## 当前边界

- 应用查询展示最多 20 行样本，主键检查也是样本检查，不代替全量质量检测。
- 运行页提供对象表格与行动入口；自由拖拽看板、三维孪生、知识库增强、通用推演属于后续迭代。
- 过滤和转换放到数据处理步骤；V1 运行页不执行绑定中的独立 transform/filter 表达式。
- 管道批次写入继续采用现有引擎，尚未提供跨管道事务或自动回滚。首次使用真实生产源前，应验证目标写入方式与备份策略。
- 元模型持久化新增 `delivery_projects`、`delivery_events` 两张表，启动时自动建表，不修改已有表结构。
